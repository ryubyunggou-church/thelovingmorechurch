## 1. 레퍼런스 분석 및 적용 계획

### 1-1. 전체 구조 요약

레퍼런스 페이지는 **히어로 배너 → 2개 탭(오시는 방법 / 주차안내) → 탭별 콘텐츠** 순서로 구성된다.

```
[VISIT US 배너 — 페이지 타이틀 + 한 줄 설명]
[탭: 오시는 방법 | 주차안내]

── 오시는 방법 탭 ──
  1) 주소/전화/팩스 카드 + 지도(카카오맵) — 좌우 배치
  2) "지하철로 오실 때" — 노선별(분당선/신분당선 등) 원형 배지 아이콘 + 환승 경로 텍스트
  3) "버스로 오실 때" — 방면별(안양방면/강남방면 등) 그룹, 버스번호 배지 + 정류장 목록

── 주차안내 탭 ──
  1) 섹션 타이틀 ("교회 주차장 이용 시 주차 요령") + 아이콘
  2) 주차장 관련 사진 2장 (건물 외관 / 지하주차장 입구) 나란히 배치
  3) 진한 색 헤더 배너("교회 주차장 / 유스페이스") + 2단 불릿 리스트로 주차 요령 안내
```

### 1-2. 섹션별 상세 분석

**① 탭 구조**

- 탭 전환은 URL을 바꾸지 않는 상태 기반 토글(활성 탭만 진한 배경으로 강조)
- 두 탭 모두 같은 배너 아래 위치, 탭 자체는 필 형태(pill) 버튼 두 개

**② "오시는 방법" — 지도 컴포넌트**

- 카카오맵 iframe/위젯을 카드 우측에 배치, 좌측엔 주소·전화·팩스 텍스트 카드
- 지도 위에 마커 + 말풍선(주소 텍스트)이 겹쳐 표시됨

**③ "오시는 방법" — Location(지하철/버스)**

- **지하철**: 노선 하나당 "원형 배지 아이콘(노선 색상) + 노선명 + 환승 경로 설명(역 → 버스/도보 → 정류장)" 1행 구성을 반복. 노선이 여러 개면 카드 안에서 구분선으로 분리.
- **버스**: 방면(목적지 방향)별로 소제목을 두고, 그 아래 버스번호(강조 색상 배지) + 경유 정류장 나열을 반복. 상단에 "가장 가까운 정류장" 안내 문장이 먼저 옴.
- 두 섹션 모두 텍스트 정보 위주이며 사진/지도는 없음 — 아이콘 + 구조화된 리스트가 핵심.

**④ "주차안내" 섹션**

- 아이콘 + 타이틀로 섹션을 열고, 실제 주차장 사진(현장감 있는 스냅샷 2장)으로 신뢰도를 높임
- 안내 문구는 표/문단이 아니라 **불릿 리스트 2열**(데스크톱 기준)로, 항목마다 강조 색상 점(●) 마커
- 예약/등록 대상, 금지 행위, 협조 요청 등 성격이 다른 항목들이 섞여 있지만 모두 같은 리스트 톤으로 처리됨

### 1-3. 우리 사이트 적용 계획

현재 `ContactPage.tsx`는 탭 없이 "교회 연락처" 카드 + 지도만 있는 단일 섹션 구조다(직전 작업에서 예배시간 섹션은 제거함). 레퍼런스 구조를 다음과 같이 응용한다.

| 구성 요소 | 레퍼런스 | 우리 사이트 적용 |
|---|---|---|
| 탭 | 오시는 방법 / 주차안내 | 동일하게 2탭 — 기존 `TabbedPage` 컴포넌트 재사용 (URL 불변, 이미 education/missions에서 검증된 패턴) |
| 오시는 방법 - 카드+지도 | 좌: 주소카드 / 우: 카카오맵 | 기존 "교회 연락처" 카드(`EditableBlock`) + 기존 네이버맵 iframe을 좌우 배치로 재배치 |
| 오시는 방법 - 지하철 | 노선별 배지+경로 | 신규 섹션. `ContactInfo`에 `subwayRoutes: {line, colorHex, description}[]` 추가 필요, 관리자 편집은 Mission/Education 리스트 편집(add/remove) 패턴 재사용 |
| 오시는 방법 - 버스 | 방면별 그룹+번호 | 신규 섹션. `busRoutes: {direction, routes: {number, stops}[]}[]` 형태로 모델링, 동일하게 관리자 add/remove 편집 |
| 주차안내 탭 | 사진2장 + 불릿 리스트 | 신규. `parkingPhotos: string[]`(최대 2장, `MediaInputField` 재사용) + `parkingNotices: string[]`(줄바꿈 Textarea → `linesToList`/`listToLines`, 이미 `AboutPastor`의 학력/경력 필드에서 쓰던 패턴 그대로 적용) |

**데이터 모델 변경 범위**: `types/content.ts`의 `ContactInfo`에 위 4개 필드(`subwayRoutes`, `busRoutes`, `parkingPhotos`, `parkingNotices`) 추가, `content-service.ts`의 `getContactInfo`/`saveDocument` 매핑 확장. Firestore `contactInfo/main` 문서 하나에 계속 병합 저장하는 기존 구조를 유지하면 컬렉션 신설 없이 확장 가능.

**단계 제안**:
1. 탭 구조 도입 (오시는 방법/주차안내) — 기존 콘텐츠를 "오시는 방법" 탭 안으로 이동, "주차안내"는 빈 틀만 우선 생성
2. "오시는 방법"에 지하철/버스 섹션 추가 (데이터 모델 확장 + 관리자 편집 UI)
3. "주차안내" 탭에 사진 + 불릿 리스트 채우기

## 2. 확정 설계 — 범용 경로 리스트 + 아이콘 선택

> 1-3의 `subwayRoutes`/`busRoutes` 두 개의 고정 타입 필드 설계를 **이 섹션 내용으로 대체**한다.

### 2-1. 왜 관리자 편집인가 (재확인)

'사랑하는교회'는 현재 건물을 소유하지 않은 임차 상태이며 이전 가능성이 실존한다. 오시는길 정보(주소·지하철·버스 경로)는 **이전 시 반드시 갱신되어야 하는 데이터**이므로, 코드 하드코딩이 아닌 Firestore 기반 관리자 편집으로 간다 — 이 사이트의 다른 모든 콘텐츠(부서/사역/뉴스)와 동일한 원칙.

### 2-2. 데이터 모델 — 고정 분류 대신 범용 리스트

지하철 노선/버스 방면처럼 **교통 인프라에 종속된 분류 체계**를 스키마에 박아두면, 이전 후 "지하철이 없는 지역"이거나 "버스 방면 개수가 다른" 경우 스키마를 또 고쳐야 한다. 대신 하나의 평평한(flat) 리스트로 통일한다.

```ts
// types/content.ts
export type RouteIconType = 'subway' | 'bus' | 'walk'

export interface ContactRoute {
  id: string
  iconType: RouteIconType
  title: string        // 예: "분당선·신분당선" / "1303 (안양방면)"
  description: string  // 예: "정자역(2번 출구) → 220번 환승 → ○○ 정류장 하차"
  order: number
}
```

`ContactInfo`에 `routes: ContactRoute[]` 필드 하나만 추가한다(1-3에서 제안했던 `subwayRoutes`/`busRoutes` 2개 필드 대신). 화면에서는 `iconType`별로 그룹핑해 "지하철로 오실 때" / "버스로 오실 때" 두 소제목 아래 나눠 렌더링하면 레퍼런스와 동일한 시각 구조를 유지하면서도, 관리자가 항목을 자유롭게 추가·삭제·순서 변경할 수 있다. 도보 안내(`walk`)가 필요한 위치로 이전하더라도 타입 추가 없이 바로 대응된다.

### 2-3. 아이콘 — 이미지 저장 대신 `lucide-react` 아이콘 매핑

요청하신 "아이콘 종류를 저장해두고 선택·적용" 흐름은 정확히 필요하지만, **별도 이미지 파일을 새로 만들어 `public/`에 저장하는 대신 이미 프로젝트에 있는 `lucide-react` 아이콘을 매핑**하는 방식을 제안한다.

- `lucide-react`(이미 의존성으로 설치돼 있고 앱 전역에서 사용 중)에 지하철/버스/도보에 정확히 대응하는 아이콘이 이미 포함돼 있음: `TrainFront`, `Bus`, `Footprints`
- `RouteIconType → 아이콘 컴포넌트` 매핑 테이블 하나만 두면 됨:

```ts
const ROUTE_ICONS: Record<RouteIconType, LucideIcon> = {
  subway: TrainFront,
  bus: Bus,
  walk: Footprints,
}
```

**이미지 에셋 방식 대비 장점**:
- 새 이미지 3장을 디자인·업로드·용량 관리할 필요 없음
- 벡터라 어떤 해상도에서도 선명하고, `text-terracotta` 등 기존 색상 토큰으로 즉시 테마 색 적용 가능 (레퍼런스의 "컬러 원형 배지" 느낌은 아이콘을 `rounded-full` 배경 원 안에 감싸서 재현)
- `EducationDeptPanel`의 `CalendarDays`/`MapPin`/`Users` 아이콘 사용 패턴과 완전히 동일한 구현 방식이라 코드 일관성 유지

**관리자 편집 UX**: 항목 추가/삭제/순서변경은 기존 `MissionEditor`(드래그 정렬 + 추가 + 삭제) 패턴을 그대로 재사용하고, 아이콘 선택만 추가한다 — 3개 아이콘을 나란히 보여주는 세그먼트 버튼(라디오 형태)에서 하나를 고르는 정도로 충분하며 별도 업로드 UI는 불필요하다.

### 2-4. 주차안내 불릿 리스트 (변경 없음)

1-3에서 제안한 대로 유지: `parkingNotices: string[]`을 Textarea(줄바꿈 기준 `linesToList`/`listToLines`)로 편집 — `AboutPastor`의 학력/경력 필드와 동일 패턴이라 추가 설계 불필요.
