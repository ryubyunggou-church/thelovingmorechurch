- 버전: v1.0
- 작성일: 2026-08-12
- 대상: 신규 교회 홈페이지 (정적 콘텐츠 중심 + 관리자 CRUD)

## 1. 프로젝트 개요

**대한예수교장로회 사랑하는교회**의 공식 홈페이지를 신규 구축한다. 사이트는 실질적으로 **정적 콘텐츠 사이트**이며, 콘텐츠 변경은 전부 자체 제작할 **관리자 모드**를 통해 이루어진다. 일반 방문자 로그인/회원가입은 없다. 메뉴는 대메뉴만 존재하고 드롭다운 서브메뉴는 두지 않으며, 각 대메뉴 페이지 내부에서 필요한 경우 탭으로 콘텐츠를 나눈다. DB 로직이 필요한 곳은 교회소식 게시판 정도이며 그 외는 전부 관리자가 직접 입력하는 구조화된 정적 콘텐츠다.

### 1.1 참고 사이트 사용 범위 (중요 — 전체 복제 아님)

irijc.co.kr(이리중앙교회)은 디자인/로직의 **부분 참고용**이며 사이트 구조 전체를 옮기지 않는다. 실제로 차용하는 요소는 다음 4가지로 한정한다.

| 참고 대상                     | 위치    | 차용 범위                                             |
| ------------------------- | ----- | ------------------------------------------------- |
| Hero Section 풀스크린 슬라이더 로직 | 홈     | 전체화면 이미지/영상 슬라이드 + 자동전환 + prev/next 컨트롤의 상호작용 방식만 |
| 퀵링크 로직                    | 홈     | 자주 찾는 정보(주보/오시는길/예배안내 등)를 아이콘·카드형으로 즉시 노출하는 패턴    |
| 이미지 배경 + 텍스트 링크 블록        | 홈     | FOSTERING/MISSION 스타일의 배경이미지 위 심플 텍스트 링크 나열 블록    |
| 정적 소개 페이지 레이아웃 로직         | 서브페이지 | 브레드크럼 + 본문 컨테이너 구조 등 Page형 템플릿의 배치 로직             |

메가메뉴(드롭다운), 6개 대메뉴+세부 서브메뉴 구조, 게시판 리스트/상세 UI, 다음세대 6부서 카드 나열 등 나머지 요소는 참고 대상이 아니다.

### 1.2 사이트 공식 명칭

이 사이트의 **공식 명칭은 "대한예수교장로회 사랑하는교회"**로 확정한다. 별도의 수정 요청이 없는 한, 공식 명칭이 노출되는 모든 위치에 이 명칭을 그대로 사용한다.

- Top Bar 로고 옆 텍스트(사이트명)
- Footer 상단 로고 텍스트 및 Copyright 라인(예: `© {연도} 대한예수교장로회 사랑하는교회. All rights reserved.`)
- 브라우저 탭 타이틀(`<title>`) 및 OG 타이틀 메타태그 — 패턴: `{페이지명} | 대한예수교장로회 사랑하는교회`
- `siteSettings.siteName` 필드 기본값(4.3 참고)

10.2에서 확인된 Claude Design 시안의 임시 로고 텍스트("THE" + "사랑하는교회" 조합)는 목업 단계의 placeholder이며, 실제 구현 시 위 공식 명칭으로 교체한다.

## 2. 확정된 아키텍처 결정

초안 문서에 병기되어 있던 선택지들을 다음과 같이 확정한다.

1. **관리자 모드 = 페이지 내 인라인 편집모드.** 별도 대시보드가 아니라, 관리자로 로그인한 상태에서 실제 방문자용 페이지를 그대로 보면서 편집 가능한 요소에 편집 UI(예: 호버 시 연필 아이콘 → 인라인 폼/모달)가 나타나는 방식.
2. **프레임워크 = React + Vite (SPA), TypeScript.** Next.js 같은 SSR 프레임워크는 채택하지 않는다. 대신 SEO는 별도 보완 조치(2.1 참고)로 대응한다.
3. **하위 탭(교회소개 3탭, 교육부서 4탭, 선교사역 2탭) = 단일 페이지 내 상태 기반 탭 전환.** 별도 URL 세그먼트를 만들지 않는다.
4. **게시판(교회소식) 보안 = 처음부터 스팸 방지 선반영.** 지금은 관리자 전용 글쓰기이지만, Firestore 규칙·요청 제한(rate limit)·향후 확장(문의/댓글) 대비 검증 로직을 설계 단계부터 넣는다.

### 2.1 SPA 선택에 따른 SEO 보완 조치

- 모든 페이지에 `react-helmet-async`로 title/description/OG 메타태그를 라우트별 동적 주입. title 패턴은 `{페이지명} | 대한예수교장로회 사랑하는교회`(1.2 공식 명칭 참고).
- 정적 콘텐츠(예배안내, 오시는길, 교회소개 등)는 변경 빈도가 낮으므로 빌드 시점 prerender(`vite-plugin-prerender` 또는 배포 후 `react-snap`)로 정적 HTML 스냅샷을 생성해 초기 크롤링 대응.
- `sitemap.xml`, `robots.txt` 수동 관리(대메뉴 7개 + 정적 서브 URL 기준).
- 탭 전환 콘텐츠는 URL에 반영되지 않으므로 크롤러 노출이 제한적 — 검색 유입이 중요한 콘텐츠(예배안내, 오시는길)는 탭이 아닌 별도 라우트를 유지해 상쇄한다.

### 3.1 대메뉴 (7개, 서브메뉴 없음)

| 교회소개 | `/about`     | 탭 3개: 교회소개 / 담임목사소개 / 사역자소개      |
| 예배안내 | `/worship`   | 리스트 레이아웃 단일 페이지                  |

게시판만 상세 페이지 라우트(`/news/:id`)가 필요하고, 그 외는 전부 단일 라우트 + 탭 상태다.

### 3.2 홈(HOME) 섹션 구성 (5개, 순서 고정)

1. **Hero Section** — 풀스크린 이미지/영상 슬라이드. 2026년 표어("옛 사람을 벗고 새사람을 입자" 등) 및 문구 3줄 오버레이. 관리자가 슬라이드(이미지/mp4/링크/문구)를 CRUD. 스크롤 다운 시 Top Bar 아래로 자연스럽게 말려 들어가는 인터랙션.
2. **담임목사 인사말** — 사진 + 짧은 인사말 텍스트, 관리자 편집 가능.
3. **교회소식 바로가기** — 최신 게시글 2~3건 카드 노출 + "더보기" → `/news`.
4. **바로가기 카드 1 (1x3 Grid)** — 교육부서 / 선교사역 / 오시는길. 파스텔톤 배경 + 호버 시 색상 전환·애니메이션.
5. **바로가기 카드 2 (1x3 Grid)** — 대한예수교장로회 총회(gapck.org) / 남경기노회 / GMS 총회세계선교회(gms.kr) 외부 링크 카드. 카드1과 동일 스타일.

### 3.3 공통 서브페이지 템플릿 (정적 소개 페이지 로직)

- 상단: "타이틀 + 부연설명"(좌측) / "현재 경로(브레드크럼)"(우측) 배치.
- 본문: 콘텐츠 유형에 따라 컴포넌트 재사용 — `<TabbedPage>`(교회소개/교육부서/선교사역), `<ListPage>`(예배안내), `<BoardPage>`(교회소식), `<ContactPage>`(오시는길).
- 공통 레이아웃 셸(`<PageShell>`)로 헤더/브레드크럼/본문 컨테이너/푸터를 감싸 재사용.

## 4. 관리자 모드 상세 설계

### 4.1 인증

- Firebase Authentication (이메일/비밀번호),  최고 관리자 admin 계정(ryubyunggou@gmail.com) **1명 한정** 발급하고 프로젝트 앱에서 최고 관리자가 부관리자 3명까지 지정할 수 있는 로직을 구현하고  일반 접속자 및 회원가입/구글 로그인 없이 모든 페이지를 볼 수 있는 권한을 부여함. 관리자 계정은 최대 4명(최고관리자 1 + 부관리자 3) 체계이며, **부관리자는 콘텐츠 CRUD·인라인 편집 권한에서 최고관리자와 완전히 동등**하다. 유일한 차이는 부관리자를 등록/해제할 수 있는 권한은 최고관리자만 보유한다는 점.
- 로그인 상태는 Firebase Auth 세션 + Firestore `admins/{uid}` 문서로 권한 검증(단순 로그인 성공만으로 관리자 판단하지 않고 admin 컬렉션 존재 여부 확인).

### 4.2 인라인 편집 동작 방식

- 관리자 로그인 시 전역 상태(`isAdminMode`)가 true로 전환되고, 편집 가능한 각 콘텐츠 블록(Hero 슬라이드, 인사말, 예배안내 항목, 탭별 소개글, 게시판 글 등)에 편집 아이콘이 오버레이된다.
- 클릭 시 해당 블록만 인라인 폼(텍스트/이미지 업로드) 또는 모달로 전환되어 수정 → 저장 시 Firestore에 즉시 반영, 방문자 화면에는 실시간 미반영(발행 전 확인 위해 "저장 후 미리보기 → 게시" 2단계 권장).
- alert는 전부 modal로 대체하고, 저장 완료/실패 등 경량 피드백은 toast로 처리(문서 요구사항 반영).

### 4.3 콘텐츠 데이터 모델 (Firestore 컬렉션 초안)

| 컬렉션                    | 용도                            | 주요 필드                                                            |
| ---------------------- | ----------------------------- | ---------------------------------------------------------------- |
| `heroSlides`           | 홈 Hero 슬라이드                   | image/video url, tag(상단 배지 텍스트: 예 "다음세대"/"주일예배"/"2026년 표어"), title, subtitle, linkUrl, order, isActive |
| `siteSettings`         | 사이트 공식 명칭, 표어, 문구 3줄, 로고, 파비콘, footer 정보 | siteName(기본값 "대한예수교장로회 사랑하는교회"), slogan, mottoLines[], footerText, contact |
| `pastorGreeting`       | 담임목사 인사말(홈+교회소개 공용)           | photoUrl, message, updatedAt                                     |
| `aboutTabs`            | 교회소개 3탭 콘텐츠                   | tabKey(church/pastor/staff), content(rich text/구조화)              |
| `staffMembers`         | 사역자 소개 목록                     | name, role, photoUrl, order                                      |
| `worshipSchedule`      | 예배안내 리스트                      | name(예: 주일오전예배), time, note, order                               |
| `educationDepartments` | 교육부서 4탭                       | deptKey, missionText, image, scheduleInfo                        |
| `missions`             | 선교사역 2탭 항목                    | type(국내/국외), name, description, order                            |
| `newsPosts`            | 교회소식 게시판                      | title, contentHtml, thumbnail, authorUid, createdAt, isPublished |
| `contactInfo`          | 오시는길                          | address, naverMapEmbedUrl(네이버 지도), phone, fax, siteUrl           |

모든 컬렉션은 Firestore Security Rules로 **읽기: 전체 공개 / 쓰기: `admins` 컬렉션에 등록된 uid만 허용**을 기본으로 한다.

## 5. 교회소식 게시판 (유일한 DB 로직 구간)

- 목록: 페이지네이션(무한스크롤 대신 페이지 번호 방식 권장 — 정적 사이트 톤에 맞춤), 썸네일+제목+날짜.
- 상세: 리치텍스트 렌더링, 조회수(선택), 목록으로 버튼.
- 에디터: 관리자 전용 WYSIWYG(Normal/H1~H6, 좌·우·양쪽 정렬, 폰트 컬러 피커 기본 + 표/이미지 삽입 옵션 추천) — `tiptap` 또는 `react-quill` 검토.
- **보안(선반영)**:
  - Firestore 규칙상 `newsPosts` 쓰기는 admin uid만 가능 — 현재는 공개 글쓰기 자체가 없어 스팸 유입 경로가 없음.
  - 다만 향후 댓글/문의 기능 확장을 대비해 Cloud Functions 기반 요청 제한(rate limit), 이미지 업로드 시 확장자·용량 검증, XSS 방지를 위한 리치텍스트 저장 시 서버측 sanitize(`DOMPurify`)를 1단계부터 적용.
  - 오시는길 문의폼(있을 경우)에는 reCAPTCHA v3 적용.

## 6. 비기능 요구사항

### 6.1 반응형 / 모바일

모든 컴포넌트·이미지·폰트 사이즈가 모바일에서 완전히 대응되어야 함. Tailwind 브레이크포인트 기준(`sm/md/lg/xl`)으로 설계, 이미지 배경 텍스트 블록·Hero 슬라이더·카드 그리드(1x3 → 모바일 1열)를 특히 검증.

### 6.2 성능

- 이미지: Firebase Storage 업로드 시 리사이즈/WebP 변환(Cloud Functions 트리거 또는 클라이언트 사전 압축).
- 코드 스플리팅: 라우트 단위 lazy load.

### 6.3 코드 품질

- 컴포넌트/로직을 기능 단위로 철저히 분해, 파일당 코드량 과다 금지(가이드 라인: 단일 파일 250~300줄 초과 시 분리 검토).
- 테스트: Vitest + React Testing Library로 컴포넌트/훅 단위 테스트 동반. 핵심 플로우(관리자 로그인, 콘텐츠 저장, 게시판 CRUD)는 Playwright e2e 별도 권장.
- 재사용 페이지 템플릿(`<PageShell>`, `<TabbedPage>`, `<ListPage>`, `<BoardPage>`)을 컴포넌트화해 신규 메뉴 추가 시 재사용.

### 6.4 공통 UI 요소

- Top Bar: 스크롤 시에도 고정(sticky), 로고는 `/logo-image/Logo-01-ko-투명.png` 사용, 로고 옆 사이트명 텍스트는 공식 명칭 "대한예수교장로회 사랑하는교회"(1.2 참고).
- Favicon / App Icon: 제공된 로고 자산 기반으로 정확히 설정.
- 위로가기(Back to Top) 버튼: 전역 적용.
- Footer: 2단 중앙정렬, 상단 로고 텍스트는 공식 명칭 "대한예수교장로회 사랑하는교회" 사용, Copyright 연도는 `new Date().getFullYear()`로 자동 갱신하여 `© {연도} 대한예수교장로회 사랑하는교회. All rights reserved.` 형식으로 표기, 연락처/메일 고정 표기. 링크는 "바로가기"(대메뉴 7개)와 "협력기관"(외부기관 3곳: 대한예수교장로회 총회 / 남경기노회 / GMS 세계선교회) 두 그룹으로 나눠 표시하며, 협력기관은 홈 바로가기 카드2와 항상 동일한 3곳을 유지한다.

## 10. 디자인 시안 검토 (Claude Design 연동)

Claude Design(claude.ai/design, "Organic" 디자인 시스템)으로 제작된 홈페이지 레이아웃 시안을 Chrome을 통해 직접 열람해 PRD와 대조 검토했다. 참고로 이번 세션에는 `claude_design` MCP 서버(코드 파일 직접 임포트용)가 연결되어 있지 않아, `_ds_bundle.js`/`styles.css` 등 원본 소스 파일 자체는 가져오지 못했고 렌더링된 화면을 브라우저로 확인하는 방식으로 검토했다. 원본 코드 레벨 반영이 필요하면 Claude Design에서 코드 내보내기/공유로 파일을 직접 전달해달라.

### 10.1 확인 결과 — PRD와 일치

- **IA**: 대메뉴 7개(HOME/교회소개/예배안내/교육부서/선교사역/교회소식/오시는길) 그대로 구현, 드롭다운 서브메뉴 없음.
- **탭 전환 방식**: 교회소개 페이지에서 "교회소개/담임목사소개/사역자소개" 3탭이 URL 변경 없이 같은 페이지 내에서 전환됨 — 확정한 "단일 페이지 내 상태 기반 탭 전환" 방식과 일치.
- **서브페이지 공통 템플릿**: 좌측 "타이틀+부연설명", 우측 "HOME / 현재메뉴" 브레드크럼 배치가 모든 서브페이지에 공통 적용됨 — PRD 3.3 정적 소개 페이지 템플릿과 일치.
- **홈 5섹션 순서**: ① Hero(풀스크린 슬라이드, 슬라이드 3장 중 하나가 "2026년 표어 — 옛 사람을 벗고 새사람을 입자") → ② 담임목사 인사말(사진+텍스트) → ③ 교회소식(최신 3건 카드+더보기) → ④ 바로가기-1(교육부서/선교사역/오시는길, 파스텔 카드) → ⑤ 바로가기-2(대한예수교장로회 총회/남경기노회/GMS 세계선교회 외부링크 카드) — PRD 3.2와 순서·구성 모두 일치.
- **오시는길**: 주소·전화·이메일 박스 + 예배시간 리스트 + 지도 이미지 슬롯으로 구성 — PRD의 `contactInfo`/`worshipSchedule` 데이터 모델과 대응됨. 단, 현재는 범용 "지도 이미지" 플레이스홀더이며 네이버 지도 API가 아직 코드로 연결되어 있진 않음(디자인 단계이므로 정상).
- **관리자 모드 컨셉**: 실제 로그인 로직 대신 Tweaks 패널에 `adminPreviewMode` 토글을 둬서 관리자 인라인 편집 UI를 미리보기 하는 방식으로 프로토타이핑됨 — 확정한 "인라인 편집모드" 방향과 컨셉이 부합.

### 10.2 확인된 이슈 / 실제 구현 시 반영할 사항

- 실제 텍스트·사진·주소·연락처는 전부 플레이스홀더(예: "경기도 OO시 OO로 00", "031-000-0000", `info@saranghaneun-church.example`) — PRD 9번에서 확정한 대로 1차는 이 상태로 레이아웃만 고정하고 관리자가 추후 교체.
- 하단 푸터의 "협력기관" 링크 목록에 **대한예수교장로회 총회, GMS 세계선교회만 있고 남경기노회가 빠져 있음** — 홈 카드 섹션(바로가기-2)에는 3개 기관이 다 있는데 푸터만 2개라 불일치. 실제 구현 시 푸터도 3개 기관으로 맞춰야 함.
- 지도는 아직 이미지 슬롯 수준이라, 실제 구현 단계에서 네이버 지도 API(위 9번 확정사항)로 교체 필요.
- 색상/타이포 톤: 크림/베이지 배경 + 다크 브라운 텍스트 + 테라코타(주황빛 갈색) 포인트 컬러, 로고는 세리프+산세리프 조합("THE"는 세리프, "사랑하는교회"는 산세리프) — 실제 Tailwind 테마 설정 시 이 톤을 기준 팔레트로 삼는다. 정확한 HEX 값은 `styles.css` 원본을 받으면 그대로 추출해 반영 가능.
