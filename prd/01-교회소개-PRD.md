## 1. 목표

`/about` 단일 라우트 안에서 **상태 기반 3탭**으로 교회·담임·사역자 정보를 보여 준다.  
방문자는 URL 변경 없이 탭만 전환하고, 관리자는 탭별 콘텐츠를 **인라인 편집 모달**로 수정한다.

### 1.1 이번 범위에서 달성할 것

1. **교회소개**: 교회전경(와이드) + 소개 본문 타이포 — **뷰포트 풀 높이 중심** 레이아웃  
2. **담임목사소개**: 인물 사진 + 학력/경력/기타 타이포 — **뷰포트 풀 높이 중심** 레이아웃  
3. **사역자소개**: 프로필 카드(사진·직분·이름) 그리드 — **인원 가변 → 페이지 스크롤**  
4. 탭별 **독립 편집 모달** (이미지 + 타이포 필드, 이미지 비율 탭별 상이)

### 1.2 명시적 비범위

- 탭별 별도 URL 세그먼트 (`/about/pastor` 등) — **만들지 않음** (상위 PRD 확정)
- 방문자 댓글·좋아요
- 사역자 상세 모달/개별 페이지 (1차는 카드 그리드만)
- Sticky Hero / 과도한 패럴랙스 (랜딩에서 확정한 절제 모션 수준만 선택 적용)

## 3. 시니어 브레인스토름 요약 (요구사항 보완)

요청 핵심을 해석하면 다음과 같다.

- **교회소개·담임**은 “긴 스크롤 소개 페이지”가 아니라, **Hero처럼 한 화면에 인상이 닫히는 풀 뷰 패널**이 우선이다.  
  그 다음 스크롤하면 Footer가 자연스럽게 보인다.
- **사역자**만 인원 증감이 있으므로 **카드 그리드 + 문서 스크롤**이 맞다.
- 편집은 랜딩과 동일한 **FormField + MediaInputField** 체계를 재사용한다.
- 이미지 비율을 탭마다 다르게 두어, “전경 / 인물 / 프로필 썸네일” 용도가 섞이지 않게 한다.

### 3.1 추가 권장 사항 (구현 시 반영)

| 주제 | 권장 | 이유 |
|------|------|------|
| **탭 UI 위치** | PageShell 타이틀 바로 아래, sticky 아님 (Header 배너와 충돌 방지) | 풀뷰 탭에서 탭바가 콘텐츠를 과도하게 가리지 않음 |
| **풀뷰 높이 계산** | `min-h-[calc(100dvh-header)]` 근사. header = Topbar + 주년/관리 배너 | 실제 “한 화면” 체감 |
| **교회소개 레이아웃** | 전경 이미지 상단(또는 좌 와이드) + 본문 타이포. 좌우 `max-w-6xl` 여백 | 가독성 + Hero와 차별 (오버레이 카피 과다 금지) |
| **담임 레이아웃** | 인물 3:4 + 학력/경력 구조화 리스트 (긴 한 덩어리 plain text만 두지 않음) | 증명사진+문단 템플릿 탈피, 편집·표시 모두 명확 |
| **사역자 CRUD** | 카드 단위 편집 + **추가/삭제/순서** (인원 변동 명시 요구) | 소개 글 1개만 있으면 운영 불가 |
| **모션** | 탭 전환 fade 짧게 + 선택적 Reveal. 풀뷰 패럴랙스 과다 금지 | 랜딩 체크포인트와 톤 일치 |
| **빈 상태** | 사역자 0명 / 이미지 없음 시 placeholder | 관리자 미입력 대비 |
| **접근성** | 탭 `role="tablist"`, 이미지 alt, 대비 | 공식 교회 사이트 |

## 4. 탭별 화면 설계

### 4.1 공통 — 페이지 크롬

```
[ Header: 로고 · 7메뉴 · (관리자 시) 관리 UI · 배너 ]
[ PageShell: 타이틀 "교회소개" + 설명 + Breadcrumb ]
[ Tabs: 교회소개 | 담임목사소개 | 사역자소개 ]
[ Tab Panel: 탭별 본문 ]
[ Footer ]
```

- 기본 진입 탭: **교회소개** (`church`)
- 탭 전환 시 스크롤 위치: 패널 상단 근처로 부드럽게 맞추거나 유지(구현 시 1안 선택 — 권장: **탭 클릭 시 패널 상단으로 스크롤**)

---

### 4.2 탭 A — 교회소개 (`church`)

#### 목적
교회의 정체성·역사·비전을 **전경 이미지 + 읽기 좋은 본문**으로 전달.

#### 레이아웃 (풀 뷰포트 패널)

```
┌─────────────────────────────────────────────┐
│  (좌우 max-w-6xl 여백)                        │
│  ┌─────────────────────────────────────┐    │
│  │  교회전경 이미지 (와이드 16:9 ~ 21:9)   │    │
│  │  object-cover, rounded-2xl          │    │
│  └─────────────────────────────────────┘    │
│                                             │
│  소제목 / 본문 타이포 (세리프 제목 + 본문)      │
│  max-w-prose ~ max-w-3xl 가독 폭             │
│                                             │
│  [편집 아이콘 — 관리자]                       │
└─────────────────────────────────────────────┘
  min-height ≈ 100dvh - header  →  스크롤 시 Footer
```

**모바일**
- 전경 이미지 전체 폭(컨테이너 안), 세로 비율 다소 높게(예: 4:3 또는 16:10)
- 본문은 이미지 아래 단일 컬럼

#### 콘텐츠 필드 (표시)

| 필드 | 설명 |
|------|------|
| `heroImageUrl` | 교회전경 |
| `title` | 섹션 제목 (기본: 교회소개) |
| `body` | 소개 본문 (복수 단락, 줄바꿈 유지 또는 단순 HTML 제한 — 1차는 plain + `\n` 권장) |

#### 이미지 사이즈 기준

| 항목 | 기준 |
|------|------|
| 용도 | **교회전경 / 건물·예배 공간** |
| 표시 비율 | **16:9** 기본 (와이드). 필요 시 21:9 옵션은 CSS object-cover로 대응 |
| 권장 업로드 | 가로 긴 사진, 최소 긴 변 1600px 이상 |
| Storage | `uploads/about/church/` |
| MediaInputField | `imageOnly`, hint에 “교회전경·가로 사진 권장” |

---

### 4.3 탭 B — 담임목사소개 (`pastor`)

#### 목적
담임목사 인물 사진과 **학력·경력·기타**를 구조화해 신뢰감 있게 전달.  
홈 인사말 밴드와 **역할 분리**: 홈=짧은 환대, 본 탭=정식 프로필.

#### 레이아웃 (풀 뷰포트 패널)

```
┌─────────────────────────────────────────────┐
│  (좌우 max-w-6xl)                             │
│  ┌──────────┐   담임목사소개                   │
│  │ 인물 사진  │   성함                          │
│  │  3:4     │   직함 (예: 담임목사)            │
│  │  세로    │                                 │
│  └──────────┘   학력                           │
│                 · …                           │
│                 경력                           │
│                 · …                           │
│                 기타 / 목회 철학 요약 (선택)     │
│  [편집]                                       │
└─────────────────────────────────────────────┘
  min-height ≈ 100dvh - header
```

**모바일**
- 사진 상단 중앙 → 이름 → 리스트 본문

**홈 인사말과의 차별**
- 홈: pull-quote + 짧은 message  
- 본 탭: 학력/경력 **항목 리스트** 중심 (긴 인사문 복붙 지양)

#### 콘텐츠 필드 (표시)

| 필드 | 설명 |
|------|------|
| `photoUrl` | 인물 사진 |
| `name` | 성함 |
| `title` | 직함 (담임목사 등) |
| `education[]` | 학력 항목 (문자열 배열) |
| `career[]` | 경력 항목 |
| `notes` | 기타 / 소개 보완 (선택, 단락) |

#### 이미지 사이즈 기준

| 항목 | 기준 |
|------|------|
| 용도 | **인물 초상** |
| 표시 비율 | **3:4 세로** (증명·프로필에 적합, 정사각 강제 금지) |
| 권장 업로드 | 인물 중심 크롭, 얼굴 상단 여유 |
| Storage | `uploads/about/pastor/` |
| MediaInputField | `imageOnly`, hint “인물 사진·세로(3:4) 권장” |

---

### 4.4 탭 C — 사역자소개 (`staff`)

#### 목적
사역자 목록을 **카드 그리드**로 보여 주며, 인원 변동에 따라 **페이지 스크롤**로 확장.

#### 레이아웃 (스크롤형)

```
┌─────────────────────────────────────────────┐
│  (선택) 탭 상단 안내 문구 — 짧게               │
│  ┌────┐ ┌────┐ ┌────┐                       │
│  │사진│ │사진│ │사진│  sm:2열 / lg:3열       │
│  │직분│ │직분│ │직분│                       │
│  │이름│ │이름│ │이름│                       │
│  └────┘ └────┘ └────┘                       │
│  … 인원 수만큼 행 추가 → 스크롤 → Footer      │
└─────────────────────────────────────────────┘
```

- **풀 뷰포트 고정 아님** — 콘텐츠 높이에 따름  
- 카드 구성 **유지**: 프로필 사진 + 직분명 + 이름 (현재 구현 유지·고도화)  
- 카드 이미지 비율: 현재 **4:3** 유지 (`aspect-[4/3]`)

#### 운영 기능 (필수)

| 기능 | 설명 |
|------|------|
| 카드 편집 | 사진·직분·이름·순서 |
| 추가 | 새 사역자 카드 |
| 삭제 | 확인 모달 후 삭제 |
| 순서 | `order` 필드 (숫자 또는 상하 이동) |

#### 콘텐츠 필드

**목록 문서** `staffMembers/{id}` (기존 모델 확장 유지)

| 필드 | 설명 |
|------|------|
| name | 이름 |
| role | 직분 |
| photoUrl | 프로필 사진 |
| order | 정렬 |

**(선택 1차)** 탭 상단 안내 문구: `aboutTabs` 중 `staff` 또는 `staffIntro` 단문 — 없으면 생략 가능.

#### 이미지 사이즈 기준

| 항목 | 기준 |
|------|------|
| 용도 | **프로필 썸네일** |
| 표시 비율 | **4:3** (현행 유지) |
| Storage | `uploads/about/staff/` |
| MediaInputField | `imageOnly`, 현재 카드 크롭 유지 |

## 5. 화면 크기 · 스크롤 동작 (요약)

| 탭 | 높이 정책 | 스크롤 |
|----|-----------|--------|
| 교회소개 | 패널 `min-h ≈ 100dvh - header` | 패널 다음 Footer 노출을 위해 페이지 스크롤 가능 |
| 담임목사소개 | 동일 | 동일 |
| 사역자소개 | 콘텐츠 가변 높이 | 인원 수에 따라 자연 스크롤 |

**좌우 여백**: 공통 `max-w-6xl` + `px-4 sm:px-6` (랜딩·PageShell과 동일 리듬).

**모바일**
- 풀 뷰 탭도 `min-h`는 유지하되, 콘텐츠가 넘치면 패널 내부가 아니라 **페이지 스크롤**로 읽기 (overflow 가둠 금지 — 작은 화면에서 본문 잘림 방지).  
- 즉 “풀 뷰를 목표로 하되, 내용이 길면 스크롤 허용”이 안전하다.

## 6. 인라인 편집 모달

### 6.1 공통 규칙

- `EditableBlock` + 관리자 연필 아이콘  
- 필드: **`FormField`(라벨+한 줄 안내)** + **`MediaInputField`(파일/URL, imageOnly)**  
- 저장: Toast 성공/실패, alert 금지  
- 이미지 비우면 **기존 URL 유지**  
- Storage 경로: `uploads/about/{church|pastor|staff}/`  
- XSS: plain text 권장. 추후 리치텍스트 시 sanitize

### 6.2 탭별 모달 필드

#### 교회소개 편집
| 필드 | 타입 |
|------|------|
| 전경 이미지 | MediaInputField imageOnly |
| 제목 | Input |
| 소개 본문 | Textarea (복수 줄) |

#### 담임목사소개 편집
| 필드 | 타입 |
|------|------|
| 인물 사진 | MediaInputField imageOnly (3:4 안내) |
| 성함 | Input |
| 직함 | Input |

| 필드 | 타입 |
|------|------|

| 직분 | Input |
| 이름 | Input |

| (목록) | 추가 / 삭제 버튼 |

## 7. 데이터 모델 (Firestore)

### 7.1 `aboutChurch` 문서 `main` (신규 권장)

교회소개 탭 전용. 기존 `aboutTabs` plain content만으로는 **이미지+구조**가 부족하다.

```
aboutChurch/main
  heroImageUrl: string
  title: string
  body: string
  updatedAt: string
```

### 7.2 `aboutPastor` 문서 `main` (신규 권장)

```
aboutPastor/main
  photoUrl: string
  name: string
  title: string          // 직함
  education: string[]
  career: string[]
  notes: string
  updatedAt: string
```

### 7.3 `staffMembers/{id}` (기존 유지·강화)

```
staffMembers/{id}
  name: string
  role: string
  photoUrl: string
  order: number
```

### 7.4 레거시 `aboutTabs`

- 마이그레이션 기간: 시드/구 데이터가 있으면 폴백  
- 신규 구현은 **7.1·7.2·7.3 우선**. `aboutTabs` 본문만 있는 구조는 단계적으로 대체.

### 7.5 Security Rules

| 컬렉션 | 읽기 | 쓰기 |
|--------|------|------|
| aboutChurch | 공개 | admin |
| aboutPastor | 공개 | admin |
| staffMembers | 공개 | admin |
